## Goal

Remove code and files from the repository that are not needed from either a development or a production perspective, while keeping the 100%-coverage threshold, the 51 test suites and all CI gates green.

## Principles

1. **Never remove behaviour that a test exercises.** The coverage threshold is 100%, so any removed branch must have its test removed or rewritten in the same change. Removing code and its test together is fine; removing code and leaving its test behind is not.
2. **No behavioural change.** The app must render and behave identically before and after.
3. **Leave the public API surface alone where it is a deliberate seam.** Action creators that a connected container dispatches are part of the module's contract even if a parameter is currently unused by the implementation.

## Changes

### 1. Redundant default exports (safe, mechanical)

Three modules export a symbol both by name and as `default`, where every consumer imports it by name. The default export is unreachable dead surface.

| File | Line | Remove |
|---|---|---|
| `src/services/firebase.js` | 54 | `export default firebaseConfig;` |
| `src/shared/defaultIngredients.js` | 19 | `export default DEFAULT_INGREDIENTS;` |
| `src/test-utils.js` | 44 | `export default renderWithProviders;` |

Verified: `renderWithProviders` is imported by name in 20+ test files; `firebaseConfig` is only ever imported as a named export (`auth.js:9`, `burgerBuilder.js:4`, `order.js:4`); `DEFAULT_INGREDIENTS` is imported by name in 4 places.

### 2. Unused named exports (safe)

| File | Line | Symbol | Why it is safe |
|---|---|---|---|
| `src/services/firebase.js` | 53 | `firebaseApp` | The local variable stays — it is needed by `getAuth(firebaseApp)` and `getDatabase(firebaseApp)`. Only the *export* is dropped; the module keeps exporting `auth` and `database`, which are the two the app consumes. |
| `src/test-utils.js` | 12 | `rootReducer` | Used internally by `createTestStore` on the next line; only the export is dropped. |
| `src/test-utils.js` | 19 | `createTestStore` | Called internally by `renderWithProviders` on line 25; only the export is dropped. |

### 3. Unused mapped prop (safe)

`src/containers/Orders/Orders.js:37` maps `error: state.order.error` into props, but the component never reads `this.props.error` — it renders `<ErrorModal />`, which selects the error from the store itself. The mapping is dead.

Remove the `error:` line from `mapStateToProps` in `src/containers/Orders/Orders.js`. The `ErrorModal` keeps reading the store directly, so the modal still appears on failure.

### 4. Stray repository files (safe)

| File | Why it goes |
|---|---|
| `database-debug.log` | A stale Firebase Emulator debug log committed by accident. It is machine output, not source, and it is already covered by the `*-debug.log` rule added to `.gitignore`. It also references the retired `demo-burger` namespace. |
| `how-to-use.txt` | A vendored note from the original course download ("Compare my code to yours…"). It documents a workflow this repository does not use — the README is now the single source of truth, and it already covers setup, the emulator and the Firebase project. |
| `promt.md` | The original task prompt list. It is a scratch input, not documentation; the plan and the README supersede it. |

### 5. Dead props (judgement call — flagged separately)

These are **not** removed in this change. Each is a documented, intentional seam in the original component API, and removing them would be an API change rather than a cleanup:

- `src/components/Logo/Logo.js:7` — `props.height`. Only the test passes it. The logo is rendered by `Toolbar` and `SideDrawer` without a height. Removing it would drop a styling affordance from a shared component.
- `src/components/UI/Input/Input.js:52` — `props.label`. Only the test passes it; the app's forms use placeholders. It is a generic form component, and the label is a legitimate slot.

They are listed here so they are on the record rather than silently skipped.

### 6. Not touched, on purpose

- **The `token` parameter threaded into `purchaseBurger` / `fetchOrders`.** The implementation ignores it — the Firebase SDK signs the request from the signed-in user, which is the security fix recorded as finding 3.4. The parameter is still part of the action creators' signature and is exercised by the connected-container tests. Removing it is a signature change across five files and their tests; it is worth doing, but as its own change rather than folded into a cleanup.
- **The `textarea` branch in `Input.js` and the `default` branch in `BurgerIngredient.js`.** Both are defensive fallbacks in generic components. They are covered by tests, and removing them would reduce the component's generality.
- **`src/shared/utility.js` — `updateObject` and `checkValidity`.** Both are used by the reducers and the auth form.
- **All `src/store/actions/actionTypes.js` constants.** Every one is dispatched or handled by a reducer.
- **All CSS Module classes.** Every standalone class selector is referenced by its JavaScript.

## Verification

1. **Lint** — `npm run lint` exits 0.
2. **Coverage** — `npm run test:coverage` still exits 0 at **100%** across statements, branches, functions and lines, with the same 51 suites and 239 tests. Any branch that loses its only covering test must be re-covered or the test rewritten.
3. **Build** — `npm run build` reports "Compiled successfully."
4. **Audit** — `npm audit --audit-level=high` exits 0.
5. **Secret scan** — the Gitleaks gate passes on the cleaned tree.
6. **Browser parity** — the app is started and the builder, auth, checkout, orders and drawer flows still render correctly, confirming no behaviour changed.
7. **Dead-code re-scan** — a follow-up search confirms the removed symbols have no remaining references and no new unused export was introduced.

## Risks

| Risk | Mitigation |
|---|---|
| Removing an export breaks an import that the grep missed | The gates in steps 1-5 would fail at build time; the browser pass in step 6 confirms runtime behaviour. |
| Coverage drops below the 100% threshold | Any branch whose only test is removed must be re-covered. The threshold fails the build if this is missed. |
| A "dead" symbol turns out to be a deliberate public seam | Only symbols with **zero** importers anywhere are removed. The judgement-call items in section 5 are explicitly excluded. |
| Deleting `promt.md` / `how-to-use.txt` loses information | The README now documents setup, the emulator workflow, the Firebase provisioning and the deployment steps — a superset of both files. |
